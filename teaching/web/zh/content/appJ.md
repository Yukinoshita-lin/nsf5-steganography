## J.1 第 1 章

P1.1：156 = 10011100₂，LSB = 0。清零后置位：156 & 0xFE = 156，再 | 1 → 157；异或：156 ^ 1 = 157。两法结果相同。

P1.2：嵌入后 [133, 132, 131, 129, 134, 130, 129, 135]，变化量 [+1, −1, +1, 0, 0, −1, +1, 0]（与 3.2 节的表逐位一致）。

P1.3：全 0 图嵌入随机比特后，全部像素在 0/1 之间被改写——直方图从“集中在 0”变成“0 与 1 各半”，值对 (0,1) 被彻底拉平；视觉上仍是全黑（值 1 ≈ 黑），但卡方统计量会瞬间飙高。视觉冗余在，统计冗余没了。

P1.4：MSB 平面严重偏斜（正整数 MSB=1 的占比高），越低的位平面越接近 50%——LSB 平面就是那张“最像抛硬币”的。

## J.2 第 1½ 章

P1½.1：量化 DC = round(−224 / 5) = −45；反量化 −45 × 5 = −225；重建平均亮度 = −225 ÷ 8 + 128 = 99.875，与原值 100 差 0.125——这就是“有损”的具体尺寸。

P1½.2：+3 → +2 是减幅（幅值 −1、保符号、LSB 翻转）；+3 → +4 虽然也翻转了 LSB，但它是**增幅**——把能量往高频推，违反 nsF5“最小改动”的纪律，并且会在系数直方图上留下“高频增强”的可检测特征。隐写修改的第一原则：能用最小的、方向确定的改动达成，就不要引入新的统计痕迹。

P1½.3：质量越高 → 量化步长越小 → 取整归零的系数越少 → 非零 AC（载体）越多 → 容量越大。反过来，低质量 JPEG 本身就是一次“大扫除”。

P1½.4：像素域容量 ≈ 8 KB、改动 108 像素；JPEG 域容量 2 205 bit、改动 117 个系数——对照 1.5.3 节的表。

## J.3 第 2 章

P2.1：250 + 10 在 uint8 里回绕为 4；3 − 5 下溢为 254（模 256）。

P2.2：b = a.copy() 或 b = np.array(a)；副本的 b.base is None，视图的 b.base is a。

P2.3：比特数 = 字节数 × 8，126 × 8 = 1008（恰为 504 的两倍，因为长度头只有 16 位不随消息翻倍）；改动数不翻倍——它由消息位与像素 LSB 的“命中率”随机决定，期望翻倍、实际有波动。

P2.4：img[:, ::2] 是水平隔列抽样，画面变瘦——但它仍是原数组的视图，修改它会改原图。

## J.4 第 3 章

P3.1：对和不变 [16, 12, 18, 14]，期望 [8, 6, 9, 7]，偏差 [+2, 0, 0, 0]，χ² = 4/8 = 0.5，df = 3，chi2_sf(0.5, 3) ≈ 0.919 —— p 值极高，四对里三对被完全拉平，“疑似随机化”。

P3.2：[128,128,131,131]：原始 f = 3；F 翻转 → [127,127,132,132]，f = 5；M 翻转 → [129,129,130,130]，f = 1。[200,201,202,203]：原始 f = 3；F → [199,202,201,204]，f = 7；M → [201,200,203,202]，f = 5。第一组在 M 下更平滑（贡献 Rm 一侧），第二组两种翻转都更粗糙。

P3.3：未嵌入时全部频数压在灰度 0，(0,1) 对的 χ² 巨大、p 值 ≈ 0（判“干净”）；嵌入随机比特后 (0,1) 对瞬间拉平，p 值 ≈ 1（判“可疑”）——本底越不平衡，嵌入后的卡方信号越强。盲区：嵌入全 0 比特时一个像素都不用改，无痕。

P3.4：满容量嵌入几乎改写全部 LSB，偶奇配对彻底拉平、位面彻底随机化——prob 与 Gn 塌缩幅度都会到极值。“藏得越多越安全”在视觉上成立、在统计上恰恰相反。

P3.5：卡方的配对拉平依然发生但集中于中间亮度段；RS 的结构塌缩因“避开纹理区”而减弱——这正是自适应隐写（如 HUGO/S-UNIWARD 一族）的设计动机，8.8 节的 SRM 特征就是冲着它们去的。

## J.5 第 4 章

P4.1：s = H₁⊕H₂⊕H₄⊕H₇ = [0,0,0]；d = s⊕m = [0,1,1] → H₆ → 翻转第 6 位，码字 [1,1,0,1,0,1,1]。错第 5 位的纠错演练：s(y) = [0,1,1]⊕H₅ = [1,1,0]；若已知目标 m，则 s(y)⊕m = [1,1,0] = H₃，定位第 3 位。注意“纠错需要知道 m 或假设 s 应为 0”——隐写提取端不知道 m，所以不做纠错，这也是隐写与信道编码的目标差异。

P4.2：p=2 时 H 列为 [1,0]、[0,1]、[1,1]，α = 2×4/3 = 8/3。600 比特：p=2 需 300 块 × 3 位 = 900 个位置，平均改 300 × 3/4 = 225 位；p=3 需 200 块 × 7 = 1400 个位置，平均改 200 × 7/8 = 175 位。p=3 用更多位置换更少改动——容量富余时总是划算。

P4.3：成立的前提是“载体 LSB 近似随机”。全 0 消息时 m 恒为 0，免改条件变成 s = 0，概率仍是 1/2ᵖ——真正的提醒是：低熵消息可被“已知消息攻击”利用（攻击者猜出消息后反推嵌入位置），第 6 章的键控因此重要。

P4.4：改动数近似翻倍——伴随式由“载体 LSB 与消息”共同决定，消息翻倍后块数翻倍、每块的改动概率不变。

P4.5：16 384 比特在 512×512（262 144 位置）里 p=3 需 5 462 块、p=6 需 2 731 块，容量都够。追求最少改动选大 p，追求定位粒度与稳健选小 p——本项目默认 p=3 是折中点。

## J.6 第 5 章

P5.1：m=[0,1] 时 d = [0,1]⊕[0,1] = [0,0]，零向量不在 H 的列里 → 免改；m=[1,1] 时 d = [1,0]，干位里位置 1 与位置 4 的列都命中——求解器按确定性次序取第一个（相同输入必得相同方案）。

P5.2：xv = [+3, 0, +1, +6, +2, +5]，湿点 = 位置 2（0）与位置 3（+1）；翻转位置 4：134 → 133（+6 → +5，合法减幅）。

P5.3：湿/干划分只在**嵌入端**约束“允许改哪里”；提取端直接按同一次序读全体载体的 LSB（干点翻转后 |c| 仍 ≥1，不会从载体集合里消失）。若湿点改由口令的伪随机数决定，嵌入会改动它自己划出的湿点之外的位置——提取端无法知道“哪些位可信”，自同步即失效。内容派生的妙处正在于：嵌入只动干点，干点翻转后图像内容变了，但“哪些位置被翻转过”由提取端从消息本身校验，无需重算湿点。

P5.4：平滑图（如渐变演示图）的像素大量落在 127/128/129，湿点密度高——nsF5 绕开它们、矩阵编码不管，后者会撞雷重试，改动数反超。结论：比较算法必须固定测试图，“谁好”是相对于图像统计而言的。

P5.5：全部载体都是湿点时干点为空，方程一般无解——项目抛 CapacityError（对照 test_capacity_error 的 16×16 全 128 用例），提示换大图/高质量/短消息。

## J.7 第 6 章

P6.1：第一步状态推进后 x = 9e3779b97f4a7c15（黄金常数本身），输出 16 294 208 416 658 607 535。

P6.2：卡点有三处——① 头部池需要 seed0（口令派生），错口令读出的“哈希”是乱码；② 乱码哈希派生的 seedB 把正文池洗成完全不同的顺序；③ 即便碰巧读回比特，长度头与内容哈希校验都会失败。拿到同口令的第二张图，攻击者可以对比两图的头部池位置是否相同（seed0 相同）——这是“多图同口令”要换主密钥的原因。

P6.3：教学项目里攻击者模型是“拿到图与源码的普通对手”，内容哈希足以让口令错误与图像篡改稳定失败；真实取证产品面对能重嵌整张图的强攻击者，必须用密钥化 MAC 把“能算哈希的人”限定为持钥者。

P6.4：会成功——另存 PNG 若像素不变，LSB 与头部比特全部完好。哈希感知没有被触发的理由：像素域锚定的是**原始封面**的字节哈希，语义是“repro/实验档案比对原图”，而不是“比对含密图”；JPEG 域则有更精巧的设计——锚是色度哈希，嵌入只动亮度 Y，色度未变则校验通过。分层理解，各安其位。

P6.5：实测约 47%～53% 的位翻转（如 6.4 节的 121/256）——多次实验取平均会非常接近 128/256。

## J.8 第 7 章

P7.1：η=10：w = 0 − 10×(−0.1) = 1.0，新损失约 0.349（仍在下降）；η=100：w = 10，干净样本的预测被推到接近 1，损失升到约 1.54——步长过大，一步跨过谷底。特征尺度越大，同样的学习率越危险。

P7.2：按伪 photo_id 分组（同源样本同折）更合理——否则“兄弟样本”同时出现在训练与验证两侧，验证分数虚高。

P7.3：假阳性（FP）——把干净图判成含密。取证场景下意味着对无辜者的怀疑，社会成本高于漏掉一张弱嵌入图。

P7.4：sklearn 的 LogisticRegression 默认带正则与不同的优化器，方向应与手算一致（w 为正），数值不必相同——这正好让你体会“同一模型，不同求解器”的差异。

P7.5：错在拿不同语料的数字比高低（RESULTS.md：不同语料的数字不可比较）——0.89 与 0.81 反映的是语料难度，不是模型强弱。

## J.9 第 8 章

P8.1：按领域知识含量排序：yenet（固定 SRM 核前置）> 143d（SRM 统计特征）> 53d/11d（手工统计）> xuNet（无领域知识）。AUC 排序基本一致（0.9541 > 0.8062 > 0.7172 ≈ 0.7128 > 0.5007）——但 143d 低于 yenet 提醒我们：“知识放对位置”之外，端到端架构的表达能力也是变量；两者不是同一台机器上的两个旋钮。

P8.2：完美模型的 ROC 是“左上角折线”：检出率 100% 时误报率 0%，AUC = 1.0；随机模型的 ROC 是对角线，AUC = 0.5。

P8.3：差异来源：你的照片风格（内容复杂度）、拍摄设备（噪声本底）、分组是否严格、样本量——任何一项都足以让 AUC 偏离 README。

P8.4：对称的问题会出现——模型把 PNG 特有的“无压缩噪声”当成异常，对真实 JPEG 部署场景产生新的误报/漏报偏移。训练分布与部署分布对齐，是比调参更优先的事。

P8.5：必选 53d：向非技术听众/评审解释判定依据、需要审计每维含义的合规场景；必选 143d：在线服务批量筛查（精度优先）、对抗强嵌入变体的研究基线。

## J.10 第 9 章

P9.1：预期前三名是确定性置换、特征统计的内层循环与文件 IO——前两者是 9.2 节的下沉对象，第三者可用缓冲读写优化。

P9.2：固定种子与输入 → 分别调用两版置换 → 逐位 diff（np.array_equal）→ 重复多组种子与规模，全部一致才放行。

P9.3：本项目的定位包含“无加速环境可用”（服务器/CI/教学机），回退保证功能与结果一致；若性能是硬需求（如在线服务），降级应改为“明确报错+要求安装”，避免静默变慢。

P9.4：改算法参数最先惊动单元层（test_core 的往返断言）；打包丢文件最先惊动系统层（冻结冒烟的第 4/5 项）。

## J.11 第 10 章

P10.1：好的怀疑点示范——“143d 对 11d 的增益有多少来自 SRM、多少来自数据扩容？”复现步骤：固定照片分组，分别训 11d 与 143d；判定标准：同协议下 AUC 差 ≥0.02 且置信区间不重叠。

P10.2：假设要可证伪（“新特征使 AUC 提升 ≥0.02”），协议必须按源图分组，判定标准写进实验脚本。

P10.3：录音回放时重点听：有没有说清数字的语料与协议、有没有把“相关”说成“因果”。

## J.12 第 11 章

P11.1：判断书的关键是引用技术事实——例如②的要点是“隐写的隐蔽性被用于欺骗特定受众”，而不是“隐写是坏技术”。

P11.2：升级方案示范（哈希键控 → HMAC）：口令经 PBKDF2 派生 HMAC 密钥；头部与正文的关键字段全部改为HMAC 覆盖；验收标准 = 原有往返测试全绿 + 新增“篡改字段必失败”用例。

P11.3：示范位置——README 的 α 公式与 efficiency.py 的实现；RESULTS.md 的 0.8062 与 train_model.py 的评估输出；GUI 的 0.2% 提示与 _embed 的统计报告。
