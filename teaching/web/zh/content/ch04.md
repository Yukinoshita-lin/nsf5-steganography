**开场问题：把 3000 比特藏进一张图，最少要改多少个像素？**朴素 LSB 的答案是约 1500 次（一半像素 LSB 不对）。但 1990 年代末 Crandall 提出的矩阵编码给出了一种交易：**用更多的位置，换更少的改动**——把像素分成块，每块 7 个位置只承载 3 个比特，并且保证每块至多改 1 个位置。改动数立刻从 1500 降到约 875。这不是魔法，是汉明码。本章把这笔交易的定价公式推导出来，并用项目实测数据对账。

## 4.1 从“每像素 1 位”到“平均每次改动藏 p 位”

朴素 LSB 每藏 1 bit 就平均改动 0.5 个像素，嵌入效率很低。如果有一种编码：每读 n 个像素组成的块，就能通过最多改动 1 个像素写入 p 位消息，改动次数就会大幅下降。这个想法叫 矩阵嵌入（Matrix Embedding），它用到的数学工具是二元汉明码。

定义嵌入效率 α = 平均每次修改所携带的比特数。理论极限是每次修改最多携带 p 位，α(p) = p·2ᵖ/(2ᵖ−1)：p=2 时约 2.67，p=3 时约 3.43，p=4 时约 4.27，随 p 增大而上升，但需要的块长 n=2ᵖ−1 也在变大。

> **新手提示｜
为什么 p 越大“越划算”？因为汉明码用 n=2ᵖ−1 个位置承载 p 位消息；p 越大，n 相对 p 的“浪费”越少，平均改 1 次能寄的信息越多。代价是块变大、可嵌入消息对载体结构更挑剔。**

## 4.2 汉明码速成：校验矩阵与伴随式

设块长 n=2ᵖ−1。构造一个 p×n 的校验矩阵 H，它的 n 列恰好是 GF(2)ᵖ 里的全部非零向量：p=3 时，七列就是二进制 1..7。把块内 n 个像素的 LSB  写成列向量 x，定义伴随式 s = H·x (mod 2)，它是一个 p 位向量。

嵌入 p 位消息 m 时，我们想通过翻转个别位，让新伴随式等于 m。因为 H 的每一 列都不同，翻转第 j 位只会把伴随式变成 s⊕Hⱼ——也就是说，任意需要的伴随式 变化都对应某一列。

计算当前伴随式 s = H·x；

若 s == m，块内无需改动；

否则求差值 d = s ⊕ m（p 位非零向量）；

在 H 中找到等于 d 的那一列，记为第 j 列；

翻转第 j 个像素的 LSB，完成（H·x′ = m）。

把 4.2 节的流程变成一张可以贴在墙上的“对账表”：p=3 时，H 的 7 列恰好是二进制 1..7 的全部非零向量，于是“伴随式差值 d”与“要翻转的位置”一一对应——查表即可，不用解方程：

| **差值 d（伴随式变化）** | **命中的 H 列** | **要翻转的像素（块内第几位）** |
| --- | --- | --- |
| [1,0,0] | H₁ | 第 1 位 |
| [0,1,0] | H₂ | 第 2 位 |
| [1,1,0] | H₃ | 第 3 位 |
| [0,0,1] | H₄ | 第 4 位 |
| [1,0,1] | H₅ | 第 5 位 |
| [0,1,1] | H₆ | 第 6 位 |
| [1,1,1] | H₇ | 第 7 位 |

这张表还藏着矩阵编码最漂亮的一个性质：**d = [0,0,0]（当前伴随式恰好等于目标）时，一个位都不用翻**。消息随机时，这种情况以 1/2ᵖ 的概率发生（p=3 即 1/8 的块“免改”）。这不是运气，是设计：n 个位置承載 p 位消息，本来就有 2^p 种伴随式状态，目标状态撞上当前状态的概率就是 1/2^p。第 5 章你会看到，nsF5 还要在这个“免改概率”上叠加一层湿纸约束。

## 4.3 手算一个 p=3 的例子

设块内 7 个像素的 LSB 为 x = [0,1,0,1,1,0,1]。列向量按二进制顺序（低位在上）：H₁=[1,0,0]，H₂=[0,1,0]，H₃=[1,1,0]，H₄=[0,0,1] 依此类推。先算伴随式：x 中取 1 的位置是第 2、4、5、7 列，做异或：H₂⊕H₄⊕H₅⊕H₇ = [0,1,0]⊕[0,0,1]⊕[1,0,1]⊕[1,1,1] = [0,0,1]，所以 s=[0,0,1]。

想嵌入 m=[1,1,0]：d = s⊕m = [0,0,1]⊕[1,1,0] = [1,1,1]。H₇=[1,1,1]，命中第 7 列，于是只翻转第 7 个像素的 LSB：x′=[0,1,0,1,1,0,0]。再算一次 s′=H·x′=[1,1,0]=m，成功。

7 个像素承载 3 位消息，但平均只需要改动 (2³−1)/2³ ≈ 87.5% 的块里改 1 位——约 0.875 次/块，折算每 3 位约 0.875 次改动，即每次改动约带 3.43 位。

理论效率 α(p) = p·2ᵖ/(2ᵖ−1) 的推导，值得用三行算草纸写清楚，因为它解释了“为什么值得”（原文 4.1 已给出公式）：每块 n = 2ᵖ−1 个位置承载 p 位；由 4.2 节，块需要改动的概率是 (2ᵖ−1)/2ᵖ，因此每块平均改动次数是 1 − 1/2ᵖ；于是

```text
α(p) = 携带比特 / 平均改动 = p / (1 − 1/2ᵖ)
     = p·2ᵖ / (2ᵖ − 1)
p=1: 2/1   = 2.00    p=2: 8/3   ≈ 2.67
p=3: 24/7  ≈ 3.43    p=4: 64/15 ≈ 4.27
p→∞ : α → p（每块最多改 1 位，极限就是“每改 1 位带 p 位”）
```

## 4.4 F5：矩阵编码 + JPEG 系数减幅

把“收缩”的连锁反应用一个具体序列走一遍，你会看到它为什么比“损失容量”更讨厌。设某块抽到的载体系数（按提取顺序）是 [+3, +1, −2, +4, +1, −3, +5]，伴随式计算指出需要翻转第 2 位。第 2 位是 +1——减幅后变成 0。此时灾难分三步发生：

1. 提取端收集载体时按“非零 AC”过滤，这个突然归零的系数从序列里消失，**后面所有系数的序号整体前移一位**——不仅是这一块，包括后续所有块；

2. 伴随式从此全错，除非把这一块整个作废、消息从下一块重新开始（F5 的做法）；

3. 作废意味着容量损失，重试意味着更多减幅、更多 +1 系数被卷进来——嵌得越满，收缩雪崩越猛。

更隐蔽的是第三层：被减到 0 的系数在直方图上留下凹痕（0 过多、±1 偏少），这本身就是可检测特征——第 5 章的湿纸编码会把这批“碰不得”的位置圈出来绕着走，一劳永逸地掐灭这场雪崩。

F5 是 Westfeld 提出的 JPEG 隐写：在量化 DCT 交流系数上做矩阵嵌入。修改“位”不是翻转 LSB，而是让系数的绝对值减小 1（例如 +3→+2、−5→−4），这样既改变 LSB 奇偶，又不容易引入显著统计异常。

问题出在“收缩”：当绝对值已经是 1 的系数被减幅，会直接变成 0。而 0 系数在 JPEG 解码里意味着“没有这个频带分量”，F5 认为它不再是合法载体，于是丢掉 这块、重试后续消息。收缩导致实际载荷变小、修改效率低于理论值，还留下 可被统计的特征。

## 4.6 小结与自我检查

矩阵嵌入以“块”为单位：n 个位置承载 p 位、至多改 1 位；

H 列互不相同 ⇒ 任意伴随式差值都能定位到唯一需要翻转的位置；

嵌入效率 α=p·2ᵖ/(2ᵖ−1)，随 p 增加但块长也增加；

F5 在 JPEG 系数上减幅嵌入，遇到 |系数|=1 减到 0 就“收缩”。

> **想一想｜
如果 F5 遇到收缩就“跳过重试”，消息还可能正确解码吗？解码端如何知道哪块被跳过？想不通没关系——第 5 章的 nsF5 用湿纸编码彻底绕开了这个难题。**

**本章小结。**矩阵编码 = 用块内冗余换改动次数：n=2ᵖ−1 个位置带 p 位、至多改 1 位、平均改动 1−1/2ᵖ 次；效率 α = p·2ᵖ/(2ᵖ−1)（p=3 时 24/7≈3.43，实测 3.38）；F5 把这套编码搬到 JPEG 系数上，用减幅代替翻转，代价是收缩。
